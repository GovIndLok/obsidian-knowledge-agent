# Agent Spec: Obsidian Notes Organizer

## Overview
The Obsidian Notes Organizer is a local ADK 2.0 agent that scans scattered notes (`.md` files) in an Obsidian vault. It extracts/applies tags, establishes semantic links between related notes (using markdown `[[links]]`), and physically reorganizes files into folder hierarchies based on topics.
To preserve privacy and work locally, it relies on custom local file system tools rather than cloud database/search services.

## Example Use Cases
### 1. Tag Extraction & Application
- **Input**: A raw note about "Active Agentic Coding" with no tags or metadata.
- **Output**: The note is updated with YAML frontmatter:
  ```yaml
  ---
  tags:
    - agentic-coding
    - ai-development
  ---
  ```

### 2. Semantic Linking
- **Input**: Note A (discusses LLM planning) and Note B (discusses agent architectures).
- **Output**: Note A is updated with a reference link to Note B (e.g., `See [[Agent Architectures]] for orchestration details.`).

### 3. Hierarchical Reorganization
- **Input**: A flat directory of notes about machine learning, recipes, and personal finance.
- **Output**: Folders named `Machine Learning`, `Recipes`, and `Personal Finance` are created, and corresponding notes are moved inside them.

## Tools Required
The agent needs the following local filesystem tools:
1. `list_vault_files`: Lists all `.md` files in the Obsidian vault (recursively, ignoring `.obsidian` configurations).
2. `read_note_content`: Reads the content and metadata of a specific note.
3. `update_note_content`: Writes/modifies a note to apply tags, frontmatter, and links.
4. `move_note_to_folder`: Moves a note file to a topic-based directory.

## Constraints & Safety Rules
- **Privacy**: No note content should be sent to external/third-party APIs except the local LLM endpoint (Gemini API via Vertex AI).
- **Destructive Actions**: The agent must NEVER delete notes.
- **Backup**: Before modifying or moving any note, a temporary backup should be made or change-logging should be tracked to ensure no loss of user data.
- **Vault Configs**: Do not touch or modify the `.obsidian` configuration folder or its contents.

## Success Criteria
- Flat/scattered notes are categorized into coherent topic folders.
- YAML frontmatter with tags is extracted and applied to notes.
- Semantic markdown links are built between related notes to form a well-connected vault network.
